# Public Repository Security Boundary

This repository is **public**. It describes a system intended for law-enforcement use against
financially motivated adversaries who are capable of reading it.

Full reasoning: [`docs/adr/ADR-010-public-repository-boundary.md`](docs/adr/ADR-010-public-repository-boundary.md).
Governing principle: **publish the design, withhold the deployment.**

## Safe to publish

Source code · architecture and ADRs · infrastructure definitions · **synthetic** datasets and the
generator that produces them · reproducible ML experiments · documentation · tests · security controls ·
mock connectors.

## Never in this repository

| Category | Examples |
|---|---|
| Real data | Citizen PII, real transactions, real account numbers, real complaint text |
| Credentials | Bank or government credentials, production API keys, tokens, private certificates |
| Intelligence | Real law-enforcement intelligence, live case material |
| Deployment specifics | Production topology, live endpoint addresses, operational thresholds, alert budgets in force |
| Derived-restricted artefacts | Model weights trained on real data (they inherit the source's classification) |

## Why some things are public that might look sensitive

Model **architecture** is published; deployed **thresholds** and **weights** are not. Security through
obscurity is not a control, and a government system's design should be auditable. An adversary learning
that Tier 2 uses LambdaMART over a bounded candidate set gains nothing operational. An adversary
learning the live alert threshold for their district gains a great deal. The boundary falls between
those two, deliberately.

## How production connectors are separated

Every external system is a **port** (`DataConnector`, `NotificationProvider`, `IdentityProvider`,
`SecretProvider`). This repository ships **synthetic and mock implementations only**. Production
connectors to NCRP, CFCFRMS and Samanvay are specified as contracts with contract tests; the
implementations are a deployment activity performed under legal authority, in a separate controlled
repository.

`ATLAS_ALLOW_EXTERNAL_NOTIFICATIONS` defaults to `false`, and partially configured real providers
**fail closed**.

## Enforcement

- `.gitignore` and `.env.example` (placeholder values only).
- `pre-commit` hooks including a secret scanner — mandatory for all contributors.
- `gitleaks` in CI over **full history**, not only the diff.
- Synthetic identifiers only. Real account numbers are never primary keys in any environment.

## If a secret is ever committed

Treat it as **compromised and rotate it immediately.** Rewriting git history is not a remedy — assume
it was cloned. Follow `docs/security/incident-response.md` and record the incident.

## Data status

**All data in this repository is synthetic.** It is generated by `simulator/` from committed seeds and
does not describe any real person, account, institution or event. Any resemblance to real entities is
coincidental and unintended.
